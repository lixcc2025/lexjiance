# GitHub 开源项目调研（2026-11-25）

用途：本软件要卖给律所、法院、检察院，属于**商用、闭源、离线**。所以除了效果，**许可证**是第一道门槛：
CC BY-NC（禁止商用）、AGPL（要求开源整个软件）的不能直接并进来，只能参考思路或自己重训。

星数、最后更新时间是查询当天的数据。「许可」一栏写「无」的，是仓库没有放许可证文件，默认不允许使用代码。

## 一、AI 合成语音检测（要模型）

| 项目 | 星 | 许可 | 最近更新 | 说明 |
|---|---|---|---|---|
| [clovaai/aasist](https://github.com/clovaai/aasist) | 316 | MIT | 2023-06 | 经典反欺骗模型，约 30 万参数，CPU 很快。用 ASVspoof 2019 训练，对新出的 TTS 泛化一般。适合当基线 |
| [TakHemlata/SSL_Anti-spoofing](https://github.com/TakHemlata/SSL_Anti-spoofing) | 186 | MIT | 2023-09 | wav2vec2 / XLS-R 自监督特征 + AASIST，泛化明显好于纯 AASIST。模型约 3 亿参数，CPU 能跑但慢，要分段 |
| [nii-yamagishilab/AntiDeepfake](https://github.com/nii-yamagishilab/AntiDeepfake) | 63 | 代码 BSD-3，**权重 CC BY-NC-SA** | 2026-10 | 日本 NII，大规模训练的 SSL 检测器，效果好。**权重禁止商用**，只能用代码自己训 |
| [QiShanZhang/SLSforASVspoof-2021-DF](https://github.com/QiShanZhang/SLSforASVspoof-2021-DF) | 75 | 无 | 2025-02 | XLS-R + SLS 分类头，论文效果好，没有许可证 |
| [xieyuankun/Codecfake](https://github.com/xieyuankun/Codecfake) | 77 | 无 | 2024-12 | 针对「神经编解码器」类新 TTS（大模型语音合成）的数据集和检测方法，这类正是现在国内主流语音合成的路线 |
| [piotrkawa/attack-agnostic-dataset](https://github.com/piotrkawa/attack-agnostic-dataset) | 62 | MIT | 2023-08 | 多数据集联合训练，提升泛化 |
| [LetterLiGo/SafeEar](https://github.com/LetterLiGo/SafeEar) | 194 | CC BY 4.0 | 2025-03 | 浙大，只看声学特征不看内容的检测，许可可商用（署名） |
| [dessa-oss/fake-voice-detection](https://github.com/dessa-oss/fake-voice-detection) | 390 | Apache-2.0 | 2022-11 | 较老，效果一般 |
| [media-sec-lab/Audio-Deepfake-Detection](https://github.com/media-sec-lab/Audio-Deepfake-Detection) | 326 | — | 2025-06 | 论文和数据集汇总，找中文训练数据用 |

**结论**：路线选「自监督语音特征（wav2vec2 / XLS-R / WavLM）+ 小分类头」，代码用 MIT 的。难点不在代码在**数据和权重**：
现成的好权重要么禁商用、要么没许可；而且公开数据以英文为主，国内常见的语音合成（豆包、海螺、Fish Audio、各家声音克隆）
覆盖不够。商用要自己整理中文真 / 假语音数据训练分类头（自监督底座 XLS-R 本身是 MIT / Apache 许可，要再核对）。

另外，国内《人工智能生成合成内容标识办法》（2025-09-01 施行）和 GB 45438-2025 要求 AI 生成的音视频在元数据里写隐式标识，
合规的国内生成工具导出的文件都应该带。这是目前最可靠的信号（v0.1 已经在读，字段名要按标准原文再核对）。

## 四、剪辑痕迹（不要模型）

GitHub 上**没有成熟的开源项目**，搜到的都是几颗星的课程作业，不少没有许可证。但方法在学术上很成熟，自己实现：

- 声音：底噪 / 背景噪声一致性（参考 [Tianziwei/Audio-splicing-detection-and-location](https://github.com/Tianziwei/Audio-splicing-detection-and-location)，4 星，无许可）、
  电网频率 ENF 连续性（[tijszwinkels/enf-timestamp](https://github.com/tijszwinkels/enf-timestamp) MIT、[geokarant/ENF_extraction](https://github.com/geokarant/ENF_extraction)）、
  数字静音、频谱断层、二次压缩痕迹
- 视频：时间戳断档和关键帧（v0.1 已做）、帧重复 / 丢帧、画面噪声一致性
- 图像篡改定位 [grip-unina/TruFor](https://github.com/grip-unina/TruFor)（287 星）效果好，但许可只限研究（压缩包里的 LICENSE.txt，要再核对），可用于视频关键帧，商用前要确认

## 总的判断

1. **剪辑痕迹**：自己做，不靠模型，云端能完整开发和测试，最先出效果
2. **来源标识**：国标隐式标识 + C2PA + 元数据工具名，便宜、准确率高，但能被删掉
3. **AI 语音 / AI 视频模型**：代码有可商用的，**可商用的好权重基本没有**，需要自己准备中文数据训练。这是整个项目最大的工作量和不确定性，要尽早定方案
